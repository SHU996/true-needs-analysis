# True Needs Filter（真需求快速过滤）

> 来源框架：梁宁《真需求》（新星出版社，2024）
> 这是 true-needs-analysis 工具包的第一步——30秒快速判断。

## 核心原则

```
真需求 = 用户 + 场景 + 痛点
三者都必须具体、可观察，不能是推断
```

大多数产品失败不是因为做得不好，而是因为建立在了**想象的需求**上。这个skill只做一件事：**用最快的速度告诉你，这个需求是不是想象出来的。**

## 使用前提

**只在用户主动要求快速验证时运行本 skill。**
- ✓ "帮我快速判断这个想法靠不靠谱"
- ✓ "值不值得做"
- ✓ "这个需求是真的吗"
- ✗ 用户想要深度分析 → 建议使用 true-needs-deep
- ✗ 用户说"我想做 X"但意图是问怎么做 → 不要拦截，直接帮他做

## 运行流程

### 只做一件事：跑这三个选择题

以**选择题**形式向用户提问——用户只需选 A/B/C，**不需要打字描述**。三个问题一次性展示：

---

**Q1. 你的用户是谁？**

- **A)** 我能说出一个具体的人——知道他/她叫什么、做什么、每天什么环节最头疼
- **B)** 大概知道是哪类人，但说不出具体个体
- **C)** 只能描述"某类用户"，比如"忙碌的上班族"

**Q2. 痛苦在哪里？**

- **A)** 亲眼观察到过——看到过帖子、投诉、吐槽，或有真实的行为记录
- **B)** 听别人提过，但没具体记录
- **C)** 逻辑推断"应该有这个问题"

**Q3. 有没有人在绕路解决？**

- **A)** 有，有人在花钱或花时间凑合处理
- **B)** 不确定，没调查过
- **C)** 没有，目前没人解决这个问题

---

### 评估规则

用户回答后，直接根据选择组合出结论：

| 选择组合 | 结论 | 下一步建议 |
|---------|------|-----------|
| 三个都选 A | ✅ 通过快速过滤 | 可以继续推进，如需深度分析可使用 true-needs-deep |
| 有 1-2 个选 B 或 C | ⚠️ 存在风险 | 指出具体哪个问题需要调查，建议补齐后再推进 |
| 三个都选 B/C | 🛑 想象中的需求 | 建议先去现场观察，收集真实证据后再回来 |

## 输出格式

给出评估后，输出以下格式的结论（简洁，不超过150字）：

```
## 快速过滤结论

**判断：** ✅ 可以推进 / ⚠️ 需要先调查 / 🛑 暂停，重新调研

**三问结果：**
- 用户：[具体 / 模糊 / 缺失]
- 痛点：[观察到 / 部分推断 / 纯推断]
- 绕路行为：[有 / 不确定 / 没有]

**最关键的风险：** [一句话指出最大的问题]

**建议下一步：** [一个具体行动]
```

## 红旗词

需求描述中出现以下词语，大概率是想象出来的：

> "应该" · "显然" · "大家都" · "逻辑上说得通" · "用户应该会需要"

遇到这些词时，在评估中明确指出"检测到红旗词，该判断可能是推断而非观察"。

## 常见合理化借口（供参考）

| 说法 | 实际问题 |
|------|--------|
| "我了解我的用户" | 了解 ≠ 观察。有具体行为证据吗？ |
| "竞争对手都在做" | 他们可能也做错了。看用户留存数据。 |
| "用户说他们需要这个" | 用户说想要 ≠ 真的会用。看行为。 |
| "逻辑上说得通" | 想象中的需求逻辑上永远说得通，这正是陷阱所在。 |
