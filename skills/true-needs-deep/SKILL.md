# True Needs Deep（真需求深度分析）

> 来源框架：梁宁《真需求》（新星出版社，2024）
> 这是 true-needs-analysis 工具包的第二步——系统性深度体检。

## 核心原则

```
快速过滤告诉你"能不能做"
深度分析告诉你"做得对不对、护城河够不够深"
```

如果 true-needs-filter 是急诊分诊，true-needs-deep 就是全面体检。这个skill会对需求做四个维度的系统性检验：三要素精度、竞品市场调研、KANO类型、价值护城河。

## 使用前提

**在以下情况运行本 skill：**
- ✓ 用户明确要求深度分析："帮我深入分析"、"做个体检"、"详细分析一下"
- ✓ 用户提出产品想法："我想做一个XX App"、"我想做一个XX网站"、"我想做一个XX工具"
- ✓ 用户已通过 true-needs-filter 快速过滤，想要进一步分析
- ✗ 用户只想要快速判断 → 建议使用 true-needs-filter
- ✗ 用户问"怎么做" → 不要拦截，直接帮他做

## 运行流程

### 第一步：三要素精度检验

以**选择题**形式让用户快速确认每个要素的具体程度——用户只需选 A/B/C，**不需要打字描述**。三个问题一次性展示：

---

**Q1. 你的用户有多具体？**

- **A)** 能说出具体姓名、职业和日常场景（比如"仓库对账员王姐"）
- **B)** 知道是哪类人，但说不出具体个体
- **C)** 只能描述大致人群（比如"忙碌的职场人"）

**Q2. 这个问题在什么场景下发生？**

- **A)** 每天固定发生，时间和地点都明确
- **B)** 偶尔发生，大概知道什么情况下触发
- **C)** 不太确定具体触发条件

**Q3. 痛点具体是什么？**

- **A)** 能说出具体什么卡住了/慢了/坏了，以及用户现在怎么凑合
- **B)** 知道有问题，但描述比较模糊
- **C)** 主要是推测"应该有这个问题"

---

| 要素 | 选 A | 选 B | 选 C |
|------|------|------|------|
| 评估 | ✅ 达标 | ⚠️ 需补充 | ❌ 缺失 |

**对于选 B 或 C 的要素**，继续用选择题追问（不要让用户大段描述）：

- **用户选 B/C** → 追问："你能从以下哪个方向补充？" A) 我认识的某个具体的人 B) 我看到过某个帖子/视频 C) 我自己就是这个用户
- **场景选 B/C** → 追问："这个问题最可能在什么情况下发生？" A) 每天固定时间 B) 特定任务触发 C) 不定期，随机发生
- **痛点选 B/C** → 追问："用户目前最可能的凑合方式是？" A) 手工/Excel 凑合 B) 用了别的工具但不满意 C) 直接放弃了没解决

追问后仍选 C 的要素，在报告中标注为"缺失"，建议用户先去现场观察。

### 第二步：竞品市场调研

三要素检验通过后，自动调用 `competitor_analysis.py` 脚本搜索互联网，获取市场竞品信息。

**执行方式：**

使用 bash 工具运行以下命令（将 `{product_desc}` 替换为用户的产品描述）：

```bash
python competitor_analysis.py "{product_desc}" -m 8
```

**脚本会自动完成：**
1. 根据产品描述生成4组搜索词（竞品分析/对比推荐/类似产品/行业现状）
2. 用 DuckDuckGo 搜索互联网，去重提取结果
3. 输出搜索结果摘要 + 分析提示词

**执行后，AI 需要做两件事：**

1. **读取脚本输出**，从搜索结果中提取：
   - 市场上已有哪些竞品？
   - 竞品的核心功能和目标用户是什么？
   - 市场是蓝海还是红海？
   - 有没有用户在抱怨现有产品？（这是真需求信号）

2. **将竞品信息用于后续步骤**：
   - 第三步 KANO 判断时，参考竞品已有的功能来判断"哪些是必备型"
   - 第四步护城河检验时，用竞品对比来评估"用户为什么会选你而不选别人"

**如果脚本执行失败**（网络问题、未安装依赖等）：
- 不要中断流程，告知用户"竞品搜索暂不可用，以下分析基于用户描述进行"
- 继续执行后续步骤，在报告中标明"竞品数据缺失"

### 第三步：KANO 类型判断

以**选择题**形式问用户——用户只需选 A/B/C：

---

**如果这个功能消失了，你的用户会怎么反应？**

- **A)** 强烈不满，完全没法接受
- **B)** 有些失望，但能凑合用别的
- **C)** 不在意，有没有无所谓

---

根据选择判断 KANO 类型：
- 选 A → **必备**（没有就愤怒，必须做到及格线，但超出不加分）
- 选 B → **期望**（越好越满意，这是核心竞争区，值得打磨）
- 选 C → **无差异**（最常见的陷阱，很多"创新"死在这里）

如果用户选了 C 但不确定，再用一道选择题反向验证：

**反向验证：如果这个功能做得特别好，用户会？**
- **A)** 很开心，会主动推荐给别人
- **B)** 还行，觉得不错
- **C)** 无所谓，不会特别在意

（反向选 A + 正向选 C = **魅力型**，可以作为差异化卖点；双向都选 C = **无差异**，建议不做）

### 第四步：价值护城河检验

以**三道选择题**让用户快速评估价值层次——用户只需选 A/B/C：

---

**Q1. 功能价值：别人如果做一模一样的功能，用户会切换吗？**
- **A)** 不会，我这边有明显优势（数据/速度/体验等）
- **B)** 可能会，看具体情况
- **C)** 大概率会切，功能层面差不多

**Q2. 情绪价值：用户用的时候，主要感受是？**
- **A)** 省心/被理解/有面子——能说出具体感受
- **B)** 就是解决问题，没什么特别感受
- **C)** 没想过这个问题

**Q3. 资产价值：用户用了一年后，还会因为什么留下来？**
- **A)** 数据/习惯/关系沉淀，走了可惜
- **B)** 可能因为用习惯了
- **C)** 想不出留下来的理由

---

**护城河评估规则：**
- 3 个都选 A → 护城河**强**
- 2 个选 A → 护城河**中**
- ≤1 个选 A → 护城河**弱**，在报告中标注"护城河不足，建议补充情绪价值或资产价值的设计"

**只有功能价值的产品容易陷入价格战。** 如果 Q2 和 Q3 都没选 A，明确提醒用户：除了"解决问题"，用户没有其他留下来的理由。

### 第五步：输出深度分析报告

运行完毕后，输出以下格式的结论：

```
## 需求深度分析报告

### 总体判断
**结论：** ✅ 可以推进 / ⚠️ 需要调整后推进 / 🛑 暂停，重新调研

### 三要素精度
| 要素 | 评估 | 说明 |
|------|------|------|
| 用户 | [达标/需补充] | [具体说明] |
| 场景 | [达标/需补充] | [具体说明] |
| 痛点 | [达标/需补充] | [具体说明] |

### 需求类型（KANO）
**类型：** [必备 / 期望 / 魅力 / 无差异 / 反向]
**判断依据：** [如果功能消失，用户会____]
**策略建议：** [对应的策略]

### 竞品市场调研
**市场成熟度：** [蓝海 / 红海 / 正在升温]
**主要竞品：**
| 竞品 | 核心功能 | 优势 | 劣势 |
|------|---------|------|------|
| [竞品1] | [功能] | [优势] | [劣势] |
| [竞品2] | [功能] | [优势] | [劣势] |
**差异化机会：** [你的产品相比竞品的机会在哪]

### 价值护城河
| 价值层 | 评估 | 说明 |
|--------|------|------|
| 功能价值 | [有/无] | [具体说明] |
| 情绪价值 | [有/无] | [具体说明] |
| 资产价值 | [有/无] | [具体说明] |
**护城河强度：** [强 / 中 / 弱]

### 主要风险（最多3条）
1. [最关键的疑点]
2. [次要疑点]
3. [第三疑点]

### 建议下一步（最多2个行动）
1. [一个具体行动]

```

## 常见陷阱

| 陷阱 | 表现 | 破解方法 |
|------|------|---------|
| **功能堆砌** | "我们可以加XX、XX、XX功能" | 回到三要素：每个功能服务的是哪个用户的哪个痛点？ |
| **伪魅力型** | "这个功能用户会很惊喜" | 魅力型的前提是"有了惊喜，没有不在意"。如果用户没它也行，那是无差异。 |
| **护城河幻觉** | "我们先做功能，沉淀以后再说" | 没有资产价值设计的产品，用户随时可以走。在第一天就要想清楚。 |
